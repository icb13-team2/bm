# 진행기록

데이터 다운캐스트 작업의 날짜별 기록이에요. 원문 문장은 적지 않고, 파일 이름, ID, 숫자만 써요.
작업이 하나 끝날 때마다 이 문서를 고치고 GitHub에 올려요.

## 2026-10-09 ~ 10-11 (이전 대화) 다운캐스트와 압축 비교

**진행사항**
- 쇼핑 라벨링 데이터(JSON 7개)를 표로 읽어서 숫자 크기를 줄였어요(다운캐스트).
- 문자열 열을 category로 바꿨어요.
- 압축 방식(snappy, lz4, gzip, brotli-11, zstd-3/9/19)을 비교했어요.
- 최종 기본 파일은 zstd-19로 정했어요.

**결과물**
- `report/01_downcast_보고서.md`, `report/02_category_압축_보고서.md`, `report/크기비교_요약.csv`
- `src/downcast_parquet.py`, `src/load_data.py`
- 원본 parquet은 개인 PC에만 있어요(GitHub 제외).

**진행 과정**
1. JSON을 읽어 열 종류를 확인했어요.
2. 정수와 실수를 작은 타입으로 줄였어요.
3. 문자열을 category로 바꿨어요.
4. 압축 방식별 파일 크기와 읽기 속도를 비교했어요.
5. 읽을 때 문자열이 string 타입이 되도록 `load_shopping()`을 만들었어요.

**입력 프롬프트(요약)**
- 데이터를 다운캐스트하고 category로 저장해 달라고 요청했어요.
- 압축 방식을 비교하고 md로 정리해 달라고 했어요.
- zstd-19로 하고 문자열 처리는 맡긴다고 했어요.

**진행사항**

- 의도 규칙을 정했어요. 화자와 같은 쪽은 `의도`, 반대쪽은 `보조의도`예요.
- 팀원 공유용 진행사항 문서를 썼어요.
- 4인 통합 대시보드 수치와 우리 수치를 견줘 봤어요.

**결과물**
- `report/03_tidy_변환_보고서.md`, `report/00_팀원공유_진행사항.md`, `report/tidy_표_요약.csv`
- `src/make_tidy.py`
- tidy parquet 3개는 개인 PC에만 있어요.

**진행 과정**
1. 대화 단위로 표를 나누고 열 이름을 정리했어요.
2. 카테고리 15개를 7개로 묶었어요.

4. 대시보드 수치와 견주고, 일치한 것과 아닌 것을 정리했어요.

**입력 프롬프트(요약)**
- tidy 형태로 바꾸고 기술통계를 넣어 보고서를 고쳐 달라고 했어요.
- 팀원에게 줄 진행사항 md를 부탁했어요.
- GitHub에 올릴 수 있는지 물었어요.
- 내가 다운캐스트한 데이터로 해도 결과가 같은지 물었어요.

**결과물**

**입력 프롬프트(요약)**
