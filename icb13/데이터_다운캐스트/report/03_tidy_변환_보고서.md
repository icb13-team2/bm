# tidy(long form) 변환 보고서

- 입력: `shopping_02_category_zstd-19.parquet` (895,071행, 대화 26,270개)
- 원문은 이 보고서에 옮기지 않았어요. 열 이름과 숫자만 적었어요.
- 저장은 중간 산출물용 zstd-3이에요. 원본 base 파일(zstd-19)은 건드리지 않아요.

## 만든 표

|:----------------|:-----------|--------:|:------------------------------------------|------:|------:|
| tidy_dialogs    | 대화 1건      |   26270 | 대화셋일련번호, 카테고리, 총턴수, 발화수, 고객발화수, 상담사발화수    |  0.19 |  0.13 |
| tidy_utterances | 발화 1줄      |  895071 | 대화셋일련번호, 문장번호, 화자, QA, 발화, 의도, 보조의도, 의도기준 | 12.96 |  0.72 |
| tidy_entities   | 발화 안의 값 1개 | 2840965 | 대화셋일련번호, 문장번호, 출처, 값, 유형                  |  6.74 |  0.86 |

## 바꾼 점

| 문제 | 처리 |
|---|---|
| 발화문이 4개 열에 나뉨 | `발화` 열 하나로 합침. 모든 행에 값이 정확히 1개라 손실 없음 |
| 의도가 2개 열에 나뉨 | 화자와 같은 쪽 열을 `의도`로 씀(고객 발화는 고객의도, 상담사 발화는 상담사의도). 두 열이 동시에 찬 2803행은 버려지는 쪽 값을 `보조의도`에 보존. `의도기준`: 화자일치열 / 반대열 / 없음 |
| 카테고리 값 15개 | 공백 제거·대소문자 정리 후 7개 |
| 도메인 열 | 값이 1개(K쇼핑)뿐이라 뺌 |
| 한 칸에 여러 값(개체명 등) | 쉼표로 쪼개 `tidy_entities`에 한 값씩 저장. 지식베이스·용어사전은 "값/유형"을 `값`·`유형`으로 나눔 |
| 대화 단위 정보 | `tidy_dialogs`로 분리. 카테고리, 총턴수, 발화수, 고객·상담사 발화수 |

## 검증

- 발화 표 895,071행, `대화셋일련번호 + 문장번호` 중복 0건
- 4개 원문 열을 합친 값과 `발화` 열이 전부 같음
- 개체 표 행수: 2,840,965 (출처별 {'개체명': 2107901, '지식베이스': 562625, '용어사전': 170439})
