# 쇼핑 라벨링 데이터 downcast 보고서 (1차)

- 원본: `../쇼핑_라벨링데이터.zip` 안의 JSON 7개 (AS, 결제, 교환, 반품, 배송, 업무처리, 주문)
- 합친 크기: 895,071행 × 15열, 대화 26,270개
- 재현: `데이터_다운캐스트/` 폴더에서 `uv run --no-project --with pandas --with pyarrow --with tabulate python src/downcast_parquet.py`
- 원문 보호: 미리보기와 통계에서 원문 컬럼(고객질문(요청), 상담사질문(요청), 고객답변, 상담사답변, 개체명, 용어사전, 지식베이스)은 글자수 `(N자)`로만 표시했어요.

## 1. 크기 비교 (downcast 전 vs 후)

| 단계                          |     MB | 원본 JSON 대비   |
|:----------------------------|-------:|:-------------|
| 원본 JSON 7개(압축 해제)           | 468.68 | 100.0%       |
| 원본 zip                      |  33.45 | 7.1%         |
| 메모리: 원본(object)             | 814.54 | 173.8%       |
| 메모리: downcast 후             | 222.03 | 47.4%        |
| parquet: 원본 object(snappy)  |  36.26 | 7.7%         |
| parquet: downcast 후(snappy) |  36.26 | 7.7%         |

- 메모리: 814.5MB → 222.0MB (72.7% 감소)
- parquet 파일: 36.3MB → 36.3MB (-0.0% 감소)
  - parquet은 원래 열 단위 압축·인코딩을 해서, 타입만 바꿔서는 파일 크기가 거의 그대로예요. downcast 효과는 주로 메모리에서 나와요.
- 값 검증: 다시 읽은 parquet와 원본을 문자열로 비교해 전부 일치했어요.

## 2. downcast 방법

| 컬럼 | 원래 타입 | 바꾼 타입 | 방법 |
|---|---|---|---|
| 문장번호 | object(문자열 "1"~"298") | `uint16` | `pd.to_numeric(downcast="unsigned")`. 최대값 298이라 2바이트면 충분해요. |
| 나머지 14개 | object(파이썬 문자열) | `string[pyarrow]` | 파이썬 객체 대신 Arrow 문자열 버퍼에 담아 메모리를 줄여요. |
| (공통) | `개체명 ` | `개체명` | 컬럼 이름 끝 공백만 지웠어요. |

- 원래 JSON에는 숫자 타입이 하나도 없어요. 그래서 숫자로 바꿀 수 있는 컬럼은 `문장번호` 하나뿐이에요.
- 빈 문자열(`""`)은 그대로 뒀어요. "해당 없음" 뜻이라 NaN으로 바꾸면 의미가 바뀔 수 있어서요.
- 저장: `to_parquet(engine="pyarrow", compression="snappy")` (pandas 기본값)
